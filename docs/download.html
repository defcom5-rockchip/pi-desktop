Download and install

Plaid Pi 5.0 for the Orange Pi 5B (Plaid Pi is the new name of Pi-Desktop). One compressed image, Plaid-Pi-5.0-orangepi5b.img.zst, and one checksum file; 1.38 GiB (1,486,451,853 bytes) to download.

Plaid Pi 5.0 on GitHub

What you need

  • An Orange Pi 5B. The original Orange Pi 5 is "supported as reported" (same chip; the 2.0.x image was reported to boot on it, this one has not been reported yet; no onboard Wi-Fi or Bluetooth, no eMMC — see KNOWN-ISSUES HW-1). Other RK3588 boards are not supported by this image.
  • A microSD card of 16 GB or more (the image is about 6.5 GiB, 6.9 GB, uncompressed and grows to fill the card on first boot), or the board's eMMC.
  • An HDMI monitor, keyboard and mouse for the first boot. 120 Hz needs an HDMI 2.1 monitor and cable; 4K at 60 Hz works on any 4K HDMI monitor.
  • A power supply rated for the board. A marginal phone charger browns out under load and looks exactly like a software crash.

1. Verify the checksum

Each release ships the image and a .sha256 file next to it. On Linux or macOS, in the folder you downloaded to:

sha256sum -c Plaid-Pi-5.0-orangepi5b.img.zst.sha256
# expected output: Plaid-Pi-5.0-orangepi5b.img.zst: OK

On Windows: certutil -hashfile Plaid-Pi-5.0-orangepi5b.img.zst SHA256 and compare with the contents of the .sha256 file. The 5.0 image's checksum is d592a48fadaac293704b1a74fad9e1a3f8c05389eab21d3ee05e2578daeaf6be; the release page has it too.

2. Write the image

Writing the image erases the card or eMMC completely. Pick one method.

GNOME Disks (Linux)

  1. Insert the card. Open Disks, select the card in the left column — check its size, not just its name.
  2. Menu (⋮) ▸ Restore Disk Image…, choose the downloaded image. Disks reads .xz images directly; for a .zst image decompress it first (zstd -d).
  3. Start Restoring, wait for it to finish, then eject.

balenaEtcher (Linux, macOS, Windows)

  1. Flash from file ▸ select the downloaded image (if Etcher refuses the compressed file, decompress it first).
  2. Select target ▸ the card. Check the size.
  3. Flash. Etcher verifies the write itself.

dd (Linux, macOS)

Find the device first (lsblk on Linux, diskutil list on macOS) and make sure it is the card, not your system disk. Replace /dev/sdX:

zstd -dc Plaid-Pi-5.0-orangepi5b.img.zst | sudo dd of=/dev/sdX bs=4M status=progress conv=fsync
sync

3. First boot

  1. Insert the card, connect the monitor, keyboard and mouse, power on. The first boot takes longer: it grows the filesystem to the whole card.
  2. Armbian's setup runs in a text console: it first asks for a root password, then a user name, a password, your real name and a shell. Plaid Pi then asks for a computer name (it suggests <user>-plaidpi). The time zone and locale are suggested from your public IP address (see the privacy page) and can be changed.
  3. After the setup you get the login screen, at this and every later boot (on 4.0 the setup session logged you in once without asking).
  4. On an HDMI 2.1 monitor, 120 Hz is in Settings ▸ Displays ▸ Refresh Rate. Plaid Pi How-To.txt on the desktop explains screen scaling at 120 Hz, how to get Google Chrome, and the apps that install on first click.
  5. Firefox, LibreOffice, GIMP, Inkscape, Thunderbird, VSCodium and Google Chrome are in the app grid as placeholders; the first click downloads the real app from its own repository (you will be asked for your password).
Wi-Fi during setup: the wizard can join a Wi-Fi network for the time-zone lookup. WPA3 and WPA2/WPA3 networks work on this image, as on 4.0; stock Armbian 26.04 refuses them (kernel patch 0006).

4. Installing to eMMC

The 5B's onboard eMMC is faster and more reliable than any microSD, and it is also where most "I installed it and the board misbehaves" reports come from: on RK3588 the bootloader and the operating system can come from different places, and copying a root filesystem onto the eMMC does not install a bootloader. Write the whole image to the eMMC, from a running Plaid Pi on a microSD, and read EMMC-INSTALL.md first — it covers identifying the right device, wiping a factory-Android eMMC, and maskrom recovery.

Something wrong?

Read KNOWN-ISSUES first. Then open an issue with your board revision, how you installed (SD / eMMC), your monitor's resolution and refresh rate, and uname -a. Security problems go through the security page.
